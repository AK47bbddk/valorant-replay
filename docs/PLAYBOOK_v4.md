# プレイブック v4：ゲームモデルで組み直す（v3 の直し）

> v3（PLAYBOOK_v3.md）の並び・見た目・付録の分け方は残し、**中身の作り方**をこの文書で置き換える。食い違うときは v4 を優先。
> 元になったフィードバック：PRX Split / LOUD Sunset の v3_test（2026-11-09）。

## v3_test で出ていた問題

| 問題 | 例 | 原因 |
|---|---|---|
| 配置の時刻がズレている | 「B 3人守り」の図が 5〜40 秒の位置の平均で、移動中の点が混ざる | 配置を開始 5〜40 秒・1:15 で取っている |
| 2 冊の文がほぼ同じ | 「片側に 3 人以上寄せるラウンド…寄せた逆側は 1 人で時間を稼ぐ」「設置されたら取り返す。速く寄るか…決めておく」が PRX でも LOUD でも出ている | 数字だけ差し替えるテンプレ文 |
| 攻守で同じ動詞 | 攻めでも守りでも「Omen・Viper が MID を取りに行く」 | 動詞の辞書が攻守共通（守りに「取りに行く」は無い） |
| 守りの形が「B 3人守り／A 3人守り／前目」しかない | 開幕プッシュ・平たく守ってローテ・カウンター配置・1-4・1-3-1 などが無い | 1:15 の人数だけで型を分けている |
| リテイク・中盤の形が無い | 「設置されたら取り返す（4/22）」の 1 行だけ | 設置後・1:15 以降の動きを分類していない |
| エリアの解説がまとめて 1 行 | Map Prio が「GREEN：Mid Bottom・A Lobby・A Sewer → 必ず 1 か所は…」 | 色ごとにまとめている |

## 1. 配置は 1:40（バリアが開く瞬間）で取る

- 守りはバリアが開く前に配置まで歩き終わっている。**守りの「配置」は 1:40 の位置**（アイコン照合の節目 `1:40`、無ければ e = −3〜+3 秒のいちばん遅い追跡の点）。
- 攻めの 1:40 は「どのバリアの後ろに何人いるか」＝**寄り（lean）**として出す（A 寄り 3・MID 1・B 1 など）。
- 図は **1:40 → 1:30 → 1:20 の 3 コマ**（同じ駒をつないで矢印）。1:15 以降はラウンドの「中盤」として別に扱う。
- 5〜40 秒の平均・クラスタは配置の図に使わない（Agent Specific の立ち位置にだけ使ってよい）。
- 1:40 のアイコンが 3 人未満しか取れていないラウンドは型の集計から外し、件数を付録に出す。

## 2. ゲームモデル（コーチの分岐図）をそのまま語彙にする

xmind「ゲームモデル」の木を `config/kb/game_model.yaml` に置き、ラウンドを**局面ごとにどのノードだったか**で分ける。冊子の見出しもこの木の並びにする。

```
攻め：ビルドアップ → バイタル → アタッキング → ポストプラント ／ 極端な状況
守り：ビルドアップ → バイタル → ディフェンス → リテイク     ／ 極端な状況
```

- **バイタル**＝エリアの中でも特に重要な場所。ロング構造・分岐・サイトへの距離・ホールドしやすさで決める。
  `config/kb/maps/<map>.yaml` の `areas[].vital: true`（手で書く。無ければ eval から：ロングか分岐が「あり」で、距離が「近／中」、ホールドが「容易／中」）。
  - コーチ指定（2026-11-09）：**Split＝A Ramps（スロープ）・MID**、**Sunset＝A Main・MID**。この 2 マップは自動で足さない（`vital: false` も手で書いてある）。
- **バイタルにつながるエリアも重要なエリア**として扱う（コーチ指定 2026-11-09）。つながりは全チームの追跡で、バイタルと 5 秒以内に行き来した回数が多い所（上位 6）。エリアカードはバイタル＋つながるエリアについて作る。
- 略号（DC・PrP・PoC・BP・BTP）は意味が確定していないので、**タグとして表示だけ**する（判定には使わない）。
  当面の読み：DC＝自分から取る、PrP＝相手の圧に応じて撃ち合う、PoC＝待って様子を見る、BTP＝時間を稼ぐ、BP＝崩し・切り替え（推定）。

### 判定のルール（データから）

使えるデータ：節目ごとのエージェントとエリア（1:40・1:30・1:15・1:00・0:40・0:20）、追跡（tracks）、10 秒ごとの人数（snaps）、キルの時刻と倒した人・倒された人、設置の時刻とサイト、first_fight、エリアの攻守の距離（ranks）。
キルの場所は「倒された人の追跡のその時刻の点」で取る。

**守り**

| 局面 | ノード | 判定 |
|---|---|---|
| 配置（1:40） | 形 | A-MID-B の人数（3 サイトは A-B-C＋MID）。名前は下の「守りの形」 |
| ビルドアップ（〜1:20） | 早く深いビルドアップ（開幕プッシュ） | 1:30 までに 1 人以上が攻め側半分のエリアにいる、または 20 秒以内に攻め側半分で撃ち合い |
| | ビルドアップカウンター | 攻めが前に出てきたエリア（first_fight）へ、そこにいなかった守りが 10 秒以内に寄って撃ち合う |
| | 正しい戦略の模索（ホールド） | 1:20 まで全員が守り側半分にいて、1:40 と同じエリアに残る |
| バイタル（1:20〜1:00） | バイタル占拠 | 守り側が取ったバイタルに 1:15 も 1:00 も 1 人以上残る |
| | バイタルリアクション | 攻めが守りの主力のいないバイタルで動いた（キル・人数の増加）ときに、主力が前に出る |
| | バイタルカウンター | 主力のいるバイタルに攻めが来て、そこで撃ち合う（キルが 2 つ以上） |
| | 単独守備 | 1 サイトに 1 人だけ残し、ほかが 15 秒以内に別のエリアへ動く |
| 中盤（1:15〜設置） | タイミングプッシュ | 1:15〜1:00 に攻め側半分へ出る（今の `timing_push`） |
| | 1 人でエリア＋人数をかける | あるゾーンが 2 人以上 → 1 人になり、その 1 人が生きたまま、別のゾーンが 2 人以上増える |
| | カウンター（リアクションディフェンス） | 攻めの主力が守りの薄いサイトに入ったあと、主力側の守りが攻めの後ろ（攻め側のエリア）から 15 秒以内にキル |
| | スタック | 設置前に 4 人以上が 1 つのサイトゾーンにいる |
| | カウンターチョーク | 主力のいるサイトのチョーク（`choke: true` のエリア）で、攻めの最初の 2 キル以内に守りが 2 キル以上 |
| | バックディフェンス | サイトの奥（守り側半分で、サイトよりスポーン寄り）まで下がって、ローテの味方が着いてからキル |
| リテイク（設置後） | ファストローテ → ファストリテイク | 設置の 5 秒前より前に逆側の守りが動き出していて、設置から 12 秒以内に取り返しのキル |
| | 囲い込み | 設置後 5〜20 秒に、生きている守りが 2 つ以上の別の入口エリアからサイトに寄る |
| | ゆっくりセットアップ | 最初の取り返しのキルが設置の 15 秒後より後で、その前に 3 人以上が同じエリアにそろっている |
| | 1 人で時間を稼ぐ・セーブ | 設置後に寄った守りが 1 人以下 |
| 極端な状況 | 人数有利（+2）／不利（−1）／アンチエコ | キルフィードの人数差、相手の購入 |

**攻め**

| 局面 | ノード | 判定 |
|---|---|---|
| 1:40 | 寄り | バリアの後ろの人数（A 寄り・MID・B 寄り） |
| ビルドアップ（〜1:15） | 早く深く狭いビルドアップ | 1:30〜1:25 に 2 人以上が同じバイタルに着き、ほかのゾーンが 1 人以下 |
| | ビルドアップリアクション | 少人数のエリアで守りの圧（そこで味方が倒される）を受けて、15 秒以内に主力が逆側のバイタルへ |
| | ビルドアップカウンター | 守りが前に出てきたエリアで撃ち合って勝つ／トレードする（5 秒以内） |
| | 正しい戦略の模索（ホールド） | 1:15 まで、どのバイタルにも 2 人以上入っていない |
| | ネガティブフィードバック（フリーズ） | 早く深く狭いビルドアップの途中で最初のキルを取られ、その後 10 秒以上だれも前に出ない |
| バイタル（1:15〜0:50） | バイタル占拠 | 取ったバイタルに 1:00 も 2 人以上いて、そこで守りを倒す・スキルを使わせる |
| | バイタルリアクション | 主力のいないバイタルで守りが動いたときに、主力が近いサイトへ |
| | ローテーション | 主力が別のバイタルへ移る（1:15 と 0:40 で主力のゾーンが違う） |
| | Joker | 1 人だけ別ゾーンにいる攻め（lurk）が、主力のアタッキングと同時か 10 秒以内に、その場所で前に出てキル |
| アタッキング | サイト占拠 | デュエリストが最初にサイトに入り（追跡）、ほかが 5 秒以内に続く |
| | ダイレクトプレー | バイタルでキルが出てから 10 秒以内にサイトに入る／設置 |
| | チャレンジ | 主力がサイトのチョークで当たって（コンタクト）、そのままサイトに入る |
| ポストプラント | チョークカウンター | 設置後のキルがサイトの入口エリアで出る |
| | 爆破狙い | サイトに 1〜2 人だけ残り、ほかはサイトから離れる。0:00 まで爆破 |
| 極端な状況 | 人数有利・不利・アンチエコ | 守りと同じ |

ラウンドは局面ごとに 1 ノード（当てはまらなければ「—」）。冊子には **件数 2 以上のノードだけ**出す。

## 3. 守りの形（1:40 の配置の型）

名前＝**形（人数）＋性格**。チーム内の呼び名があれば `names.yaml` で置き換える。

| 性格 | 判定（1:40〜1:20） |
|---|---|
| 開幕プッシュ（<エリア>） | 上の「早く深いビルドアップ」 |
| 平たく守ってローテ | どのサイトも 3 人以下・MID 含め 2 ゾーン以上に人がいて、最初の接触から 10 秒以内に 2 人以上がそのサイトへ動く |
| カウンター配置 | サイトでも攻め側半分でもないエリア（リンク・MID の裏・ヘブンの横など、`areas[].counter: true` か、追跡で「接触の後に攻めの横・後ろへ出た」場所）に 1 人以上 |
| スタック | 1 つのサイトに 4 人以上 |
| 形だけ | 上のどれでもない：「2-1-2」「1-3-1」「1-0-4」 |

例：「1-3-1 開幕プッシュ（Mid Mail）」「2-0-3 平たく守ってローテ」「1-0-4 B スタック」。v3 の「B 3人守り」は形と性格に分け直す。
同じ形でも性格が違えば別の型。上位 6 型まで本編、残りは付録。

## 4. エリアは 1 つずつ解説する

Map Prio のスライドは「全体図（4 色）」1 枚だけ残し、その後ろに**エリアごとに 1 枚**（小さなエリアは 2 つで 1 枚まで）。対象はバイタルと、バイタルにつながるエリア。

**守りのエリアカード**
- 見出し：エリア名・色（Map Prio）・バイタルかどうか・評価（ロング／分岐／距離／ホールド）
- 1:40 の人数（いつも何人か：「1 人 70%・0 人 20%・2 人 10%」）と誰が立つか
- 守り方（1 つ選ぶ）：前に出て取る／その場でホールド／スキルだけ置いて人は下げる／空けてリテイク
- 攻めがここに来たとき：どう返したか（ノード名）と結果（「バイタルカウンターで 5 回中 4 回勝ち」）
- 見本の動画 1 本

**攻めのエリアカード**
- 見出しは同じ
- 何秒で・何人で取るか（「1:28 ごろに 2 人。Omen のスモークの後に入る」）
- 相手はここをどう守っていたか（相手の 1:40 の人数）
- 取ったあとどこへ行ったか（次のエリア・設置サイトの内訳）
- 見本の動画 1 本

色の意味（GREEN／YELLOW／RED／BLUE）は v3 のまま。ただし文は**エリアごとに**書く。

## 5. 文の作り方（テンプレ文を出さない）

- 本編の 1 文には、このチームのこのマップのデータから来たもの（エリア名・エージェント・人数・時刻・相手の型）を必ず 1 つ以上入れる。入れられない文は付録の「用語」へ。
- 禁止文リスト（`deck.GENERIC`）：「片側に 3 人以上寄せるラウンド」「寄せた逆側は 1 人で時間を稼ぐ」「速く寄るか、人数をそろえてからか決めておく」「最初のキルを取りに行く」など。v3_test 2 冊の両方に出た文はすべてここへ。
- 動詞は攻守で別の辞書：
  - 守り：前に出て取る（プッシュ）／ホールドする／アンカー／浮く／ローテする／下がって時間を稼ぐ／囲う
  - 攻め：取りに行く（コントロール）／詰める／見せる／裏を取る（lurk）／入る（エントリー）／切り替える
  - 守りの行に「取りに行く」が出たらテストで落とす。
- エージェントの 1 行は **1:40 の場所 → 1:20 の場所 → 中盤のノードでの役**：「Viper：1:40 は B Site、1:20 に B Main へ出てスモーク。攻めが A に来たら A Link からカウンター」。

## 6. 本編の並び（v3 からの変更）

表紙 → **バイタルの地図**（全体図＋バイタルの一覧）
→ 守り：Map Prio 全体図 → エリアカード → 守りの形（1:40、最大 6）→ 中盤の形 → リテイクの形（サイトごと）→ ULT・Micro Plays・見せて刺す
→ 攻め：Map Prio 全体図 → エリアカード → 1:40 の寄りとビルドアップ → バイタル（占拠・リアクション・ローテ・Joker）→ アタッキング（サイト占拠・ダイレクト・チャレンジ、「(From <デフォルト>)」付き）→ ポストプラント → 見せて刺す
→ 極端な状況（人数差・アンチエコ）→ ピストル → 付録。

Objectives のスライドは**ゲームモデルの要約**に置き換える：局面（ビルドアップ／バイタル／アタッキング or ディフェンス）ごとに、このチームでいちばん多いノードと 2 番目、それぞれの見本 1 本。

## 受け入れ条件

- 守りの形の図はすべて 1:40 の位置（図の下に「1:40」と出る）。5〜40 秒の平均は使っていない。
- PRX Split と LOUD Sunset の 2 冊で、本編の文（見出しを除く）の重なりが 10% 以下。禁止文リストの文は 0。
- 守りの形が 1 冊に 3 型以上（データにあれば開幕プッシュ・平たく守ってローテ・カウンター配置・スタックのどれかが入る）。
- リテイクの形がサイトごとに出る（ファスト／囲い込み／ゆっくりの内訳と見本）。
- エリアカードがバイタルの数以上あり、1 枚に 1 エリア（多くても 2）。
- 守りのエージェントの行に「取りに行く」が無い。
