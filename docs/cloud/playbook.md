# クラウドセッション用の作業指示：プレイブックの型の認識をコーチの書き方にそろえる

このリポジトリ（`vreplay`）のプレイブック（Notion の「{map} {team} Comp PlayBook」と HTML スライド）で、
型の見分け方・名前がコーチ（ユーザー）の書き方からずれている。これを直す。

## 進め方

- まず PROMPT.md と README.md を読む。文字列・コメント・コミットメッセージは日本語（今のコードと同じ、平易で具体的な書き方）。
- 主に触るファイル：`vreplay/deck.py`・`vreplay/notion_playbook.py`・`vreplay/patterns.py`・`vreplay/llm.py`・`vreplay/flow.py`、
  `vreplay/tactics.py` の `setup_of` / `setup_name` まわり。`pipeline.py`・`notion.py`・`reasons.py`・`extract.py` は
  別のセッション（docs/cloud/verify.md）が触るので、どうしても必要なとき以外は変えない。
- テストは `python -m pytest -q`（ネットワーク不要、約 120 件・1 分）。コミットの前に全部通すこと。新しい動きにはテストを足す
  （`tests/deckfx.py` が合成の report.json を作る。`tests/fixtures/split_callouts.json`・`sunset_callouts.json` は実際のコールアウト）。
- ブランチ `claude/playbook-recognition` にコミットして push する（main には直接 push しない）。小さく区切って早めにコミットする。

## コーチの資料（正解の語彙）

1. Notion の手書きプレイブック「delight split vyse comp」（Split）
   - `# 概要` → `## ATK summary`（短い文：「デフォして2巡目のアクションして最終形に持っていく」「→中盤以降のショットコールが大事」
     「A、Bヘブン取れたときの壁炊いてローテートの動きは強い」「たまにやるBメイン、ランプ、ベントのQQを刺せたら主導権が握りやすそう」）
     → ATK のデータベース → `## DEF summary`（「ドライに対して→スタンや壁、フラッシュのカウンター」「セットに対して→…分断した後の後続の
     寄りの速さで勝つ」「唯一攻めオペ出されるときつい」）→ DEF のデータベース → `## メモ`（「deadlock wall 1:10-20」「まあまあリテイク多め」）
   - ATK の行：「1-3-1 mid default」「3-1-1 B default」「ramp default」「vent default」「A skye dog default」「B default」
     「A execution」「B execution」「B split」
   - DEF の行：「default」「Anti eco」「nanamekabe default」「MID 2senti」「Ramp counter」「mid focus」「b maeme default」（B 前目）
     「a site wall default」「retake」「A push default」「B vise default」
   - 行のページ：左に例のラウンドの動画（YouTube の ?t=）、右にミニマップの画像
2. Canva「サンセット」：攻め重要エリア（「毎回BテイクしてるからカウンターケアでA行こ」「Bテイクデフォ」）／MIDを使った攻め方
   （「Bメインを取りつつAは詰め待ち」「(読まれていたら固まってメインラッシュ)」「Bメイン捨てスプリット」「TOP切り返しマケスプリット」
   「TOP Aメイン捨て」）／設置後の動き（サイトごとに遅延する場所・撃ち合う場所）／MID抜けの注意点／守りデフォ（「B２センチも可」）
   ／タイルプッシュセット／カメラカウンター／「基本ドライ」
3. Canva「TryOut」：ATK＝索敵CCブリンク／ポストプラント（設置中に下がる・当たる・時間を稼ぐ）／エントリーセットアップ。
   DEF＝3人で守る（壊す・返す・倒す）／タイミングプッシュ（1巡目のデフォルトからリグループのタイミングを狙って詰める）／ファストリテイク
4. Canva「安く取る／高く取る」：エリアを安く広く取る（スモーク＋シグネチャー）か、高く取ってボーダーの敵を倒す（スモーク＋フラッシュ＋ブリンク）か

まとめると、コーチの型の分け方は
- ATK：「<取りに行く場所> テイクデフォ / default」（B Main・Ramp・Vent・Top/Mid・A Main・Heaven など場所の名前）、形の名前「1-3-1 mid default」、
  2 巡目のアクション「<サイト> execution」「<サイト> ラッシュ」「<見せた場所> 捨て <サイト> スプリット」「<サイト> レイト」、サイト別のポストプラント
- DEF：「守りデフォ（形）」「<サイト> 3人守り」「<場所> 前目 / push」（早い時間に攻め側のエリアを取る）、「タイミングプッシュ」（1:15〜1:00 ごろ）、
  「<場所> カウンター」（攻めのデフォルトに早い先制キル）、「mid focus」、「<サイト> リテイク」（ファストリテイク／遅いリテイク）、「Anti eco」「Pistol」

## 今の出力（実データ：Split G2 Comp PlayBook、3 マップ・62 ラウンド）の問題

- ATK：「B Site Set」(1)「B Late Set」(1)「A Split（MID → A）」(2)「A Site Set」(2、購入に Pistol が混ざる)「B Split（MID → B）」(4)
  「A Site Rush」(4)「A Late Set」(4)、デフォルトは「4-1-0 A 寄せ #6」(1)「#5」(1)「4-0-1 A 寄せ #4」(1)「5-0-0 A 寄せ #3」(1)
  「2-2-1 A/Mid 分割」(2)「2-1-2 A/B 分割 #1」(2)「5-0-0 A 寄せ #2」(2)「5-0-0 A 寄せ #1」(3) と、1 ラウンドだけの断片が並ぶ
- DEF：「B retake」(11・45%)「A retake」(15・20%)「5-0-0 A スタック #2」(1)「2-1-2 バランス #1」「2-0-2 サイト守り（MID なし） #1」
  「1-2-2 MID 2 #3」「1-2-1 MID 2 #2」「2-2-1 MID 2 #1」「1-0-4 B スタック #1」「5-0-0 A スタック #1」(3、ピストル込み)
- 試合ページの初動（開始 6〜20 秒）が「攻め A 寄せ A5」「守り A スタック A3 B2」「MID 3 A1 Mid4」など、スポーンや移動中の点に
  引っ張られている（Split の守りが A に 5 人はありえない）
- LLM の ATK summary が文の途中で切れていた（「…（遅めのセット 8 回・勝率 100%、設置後勝率 14/18・」）。DEF summary は出ず、強み／弱みの箇条書きに戻っていた

## やること

1. 初動の取り方：スポーンのコールアウト・攻撃側／防衛側のスポーン区域の点は数えない。散ったあと（15〜25 秒・1:15 の節目を優先、
   なければ 6〜20 秒）で取る。形の文字列は A-Mid-B の人数（「1-3-1」。3 サイトのマップは A-B-C と Mid を分かりやすく）のまま。
2. 取りに行く場所（キーエリア）：チーム×ラウンドごとに、スポーン以外で 2 人以上が入っているコールアウト（無ければいちばん前に出ている所）
   を、valorant-api の実際の名前（「B Main」「Mid Vent」「A Ramps」「B Tiles」など）で決める。ATK のデフォルトは
   「<キーエリア> テイクデフォ」、決まらなければ「<形> <ゾーン> default」。DEF は上の分け方。「#1/#2」の番号はやめ、同じ名前は 1 つにまとめる
   （本当に違う型はキーエリアで呼び分ける）。1 ラウンドだけの型は、人数の差（A/Mid/B の L1 距離）1 以内の近い型（同じキーエリアを優先）
   にまとめるか「その他」に入れる。デフォルトの行は攻守それぞれ多い順に 6 つ程度まで。
3. ピストル・エコ（セーブ）のラウンドはデフォルトの集計から外し、攻守それぞれに「Pistol」「Anti eco」の行を作る
   （ラウンドの種類は `vreplay/flow.py`：ピストル／アンチエコ／ボーナス／フルバイ／対フォース／フォース／ハーフ／エコ）。
4. ATK の 2 巡目：「<サイト> execution」（デフォルトからのサイト取り）、「<サイト> ラッシュ」（30 秒以内に設置など）、
   1:15 のキーエリアと設置サイトが違えば「<見せた場所> 捨て <サイト> スプリット」（`deck.branch_groups`・`flow` のフェイク判定を使う）、
   「<サイト> レイト」（60 秒以降に設置）。「（MID → A）」のような細かい経路はタイトルでなく本文に。サイト別「<サイト> ポストプラント」（設置後の勝率）。
5. DEF：「<サイト> リテイク」をファストリテイク（設置から 10〜12 秒以内に解除・最初の取り返しキル）と遅いリテイクに分けるか本文で区別。
   設置前に守りが早い先制キル（20 秒以内）で勝ったラウンドを「<場所> カウンター」（場所は `tactics.fight_zone`）。
   デフォルトのあと 1:15〜1:00 ごろに守りが攻め側のコールアウトに出ていれば「タイミングプッシュ」。
6. Notion のデータベース：タグは「形」と「解説の言及」を分ける。ピストルでない型の購入に Pistol を付けない。種類の選択肢を
   Default／Execute／Split／Rush／PostPlant／Retake／Counter／Push／Pistol／AntiEco に広げる（日本語でもよい）。
7. LLM の要約を壊れにくく（`vreplay/llm.py`・`notion_playbook._summary_lines`・deck）：Gemini の考える分も見込んで max_tokens を増やす。
   出力が途中で切れている（最後の行が 。／）／)／」 で終わらない）か ATK／DEF の片方が無ければ、短めに書くよう言い直して 1 回だけやり直し、
   だめなら側ごとに従来の箇条書きに戻す（全部か無しかにしない）。書き方はコーチ風の短い箇条書き：デフォルト → 2 巡目のアクション → 最終形、
   強いところ、対策（「ドライに対して→…」「セットに対して→…」）、データに無いことは「推測：」。プロバイダーの順と決まりは PROMPT.md のとおり
   （`llm.provider: anthropic` と書いたとき以外 Claude の API は使わない）。
8. HTML のスライド（`deck.build_deck`）も同じ名前・行にする。README.md と PROMPT.md のプレイブックの節を短く更新する。

## 確認

`tests/deckfx.py` を広げ（Split の実際のコールアウト・スポーンの点・ピストルとエコのラウンド・フェイクを含める）、そこから作った
ATK／DEF の行の名前を変更の前後で出して、最後の報告に載せる。報告：ブランチ・コミット・前後の行の名前・新しい決まりの説明・残った課題。
