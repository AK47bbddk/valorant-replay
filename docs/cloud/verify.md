# クラウドセッション用の作業指示：試合解析の自己検証とバグ修正

このリポジトリ（`vreplay`）が作った試合のマップページ（Notion「マップ詳細」・HTML）に、明らかなおかしさが残っている。
今のコードでも起きるかを確かめて直し、report.json の矛盾を自動で洗い出す仕組みを作る。

## 進め方

- まず PROMPT.md と README.md を読む。文字列・コメント・コミットメッセージは日本語（今のコードと同じ、平易で具体的な書き方）。
- プレイブックまわり（`deck.py`・`notion_playbook.py`・`patterns.py`・`llm.py`・`flow.py`、`tactics.setup_of / setup_name`）は
  別のセッション（docs/cloud/playbook.md）が触るので変えない。
- テストは `python -m pytest -q`（ネットワーク不要、約 120 件・1 分。動画は落とせない）。コミットの前に全部通すこと。テストを足すこと。
- ブランチ `claude/verify-fixes` にコミットして push する（main には直接 push しない）。小さく区切って早めにコミットする。

## 見つかった問題（2026-10-25 に作られた TYLOO vs G2 Esports・Sunset・Champions 2026 のページ。その後コードは変わっているので、まず今も起きるかを確かめる）

ページの先頭の灰色の行：「レイアウト riot（タイマー 9/18 枚）／…／キルフィード 自動検出（9 行）／…／キル キルフィード 0・カードで補完 52・全滅から補完 22／…」

1. キルフィードの行は 9 本見つかったのに、読めたキルが 0 → 全部「（G2・キル不明）→ 被キル」。`extract.py` の行の検出〜OCR の流れで、
   行があるのにキルにならない理由を調べる（`tests/fixtures/killfeed_strip_*.jpg`・`panels_riot_*.jpg` とテスト）。論理のバグなら直す。
   少なくともページの先頭で「キルフィードが読めていません」とはっきり出し、ログに原因を調べる手がかりを出す。
2. 設置後のキルの時刻が「spike」という文字で出る（「spike （TYL・キル不明）→ trent」。タイマーがスパイクのアイコンに変わるため）。
   経過時間か、設置時刻から計算した「設置後 0:12」で出す。R3 は 💀全滅（攻撃）の勝ちなのに 5 人の死亡が spike の時刻になっていた。
   スパイクの爆発の扱い（`pipeline.spike_deaths`）が爆発で終わったラウンドだけに効くこと、表示が紛らわしくないことを確かめる。
3. キルが時刻順に並んでいない（R8：残り 0:44、0:43、0:48、0:39、0:38）。時刻順に並べる。
4. 仮の名前が残る：「G2 フル 26.2k 左1 ? / 左2 ? / 左3 ? / 左4 ? / 左5 ?」「ULT 開始時に溜まっていた：右4」。PROMPT.md では
   1 マップの中でカードの並びは変わらないので、ほかのラウンドの多数決で埋めることになっている。その処理を確かめて直す。
   どうしても分からなければ「左1」「右4」ではなくエージェント名か「（不明）」、武器が 5 人とも「?」なら「武器を読めず」と出す。
5. 「先制キル」の列が「?→splash（G2）」。キラーが分からないときはキルログと同じ「（G2）→ splash」にして、倒された側のチームも分かるように。
6. 全滅からの補完で 5 人の死亡が同じ秒（R9 の 0:59 ×5）になる。表示で「推定」と分かるようにする。
7. R1（解除で決着）のキルが「-」（0-0）。決着がついたラウンドでキルが 0 件なら印をつける。

## 自己チェックの仕組み

`vreplay/verify.py` と CLI `vreplay verify <report.json か出力フォルダ>` を作る。report.json を読んでマップごとに問題を並べる：

- スコアの推移が VLR と合うか、ラウンド数
- ラウンドごとのキル数と生存人数（1 チームの死亡は 5 まで、全滅勝ちなら相手の死亡が 5）
- キラー不明の割合、キルフィードの行があるのに読めたキルが 0
- キルの時刻の順番の乱れ・ラウンドの外の時刻、爆発で終わっていないラウンドの spike の時刻
- 仮の名前（左N／右N／?）、武器が全員不明
- 購入額とエコ区分の食い違い、ラウンドの終わりより後の設置
- そのチームにいない選手の ULT、同じ選手がラウンド内で 2 回倒される
- 勝ち方と矛盾する勝因（設置が無いのに「ポストプラント成功」、攻撃側の勝ちなのに「リテイク」など）

毎日の実行でも各マップのあとに走らせ、ログに短くまとめ、Notion・HTML の先頭の灰色の行に「自己チェック：n 件」を 1 行出す。
失敗しても実行全体は止めない。report.json の形は `pipeline.py`・`report.py`・テスト（`tests/test_outputs.py` など）から読み取り、
テスト用の合成データを作る。README.md と PROMPT.md に verify と直した点を短く足す。
