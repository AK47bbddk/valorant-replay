# プレイブック v5：マップ × 5人構成のページ（図が主役）

> この文書が v5 の仕様の正本。`vreplay/playbook_v5.py`・`scripts/playbook_v5.py`・
> `scripts/validate_playbook_v5.py` はこの文書に合わせる。食い違ったらこの文書を直してから実装を合わせる。
> v4（`PLAYBOOK_v4.md`・`vreplay/playbook_v4.py`）はチーム単位のレポートのまま残す（置き換えない）。

## 目的

v4 は「チーム単位・集計を文章で並べたレポート」で、図が少なく、構成が混ざり、型が細切れで、
攻めのページが空になりがちだった。v5 は単位を **「マップ × 5人構成」** に変え、
**図（マップ図・動く図・VODカード）を主役** にしたページを構成ごとに 1 つ作る。

## データと単位

- 入力は `report.json` のリスト。`deck.records()` で全ラウンドを取り、`--map` で絞る。
- 構成キーは各レコードの `comp_key`（5エージェントの完全一致）をそのまま使う。
  `comp_key` が無い・空・`None`・`?` を含むラウンドは「構成不明」として集計から外し、数を数える。
- 環境フィルタ：`date >= ENV_START` のラウンドだけをページ対象にする。
  それより前のラウンドは index の「旧環境」集計にだけ使う（ページは作らない）。
- マップ画像が用意できないときは生成全体を失敗させる。「画像なし」の HTML は出さない。取得は最大 3 回試す。
- マップ画像のキャッシュは `<out>/_work/_cache` に自己完結させる。
- 側ごとの使用可否：`gamemodel.setup_at_140(r, model)` が `None` でないラウンドを「使用」。
  構成ページの総数 = 守りの使用 + 攻めの使用 + 除外（setup が取れなかった環境内ラウンド）で必ず一致させる。
  ピストルは使用数に含める（型・手札の集計からは除く）。

## 設定値

モジュール冒頭の定数として持ち、各ページの付録スライドにも同じ一覧を出す。

| 定数 | 値 | 意味 |
|---|---|---|
| `ENV_START` | `"2026-09-01"` | これ以降の日付のラウンドだけをページ集計に入れる |
| `ENV_LABEL` | `"Champions 2026"` | 現在の環境の呼び名 |
| `PAGE_MIN_ROUNDS` | `30` | 環境内の構成ラウンド数の下限 |
| `PAGE_MIN_FULL5` | `15` | 1:40 で5人そろったラウンド数の下限 |
| `PAGE_MIN_SETUP_RATE` | `0.60` | setup が取れたラウンドの割合の下限 |
| `PATTERN_MIN` | `3` | 型（配置クラスタ）の成立ラウンド数 |
| `PATTERN_DIST` | `0.09` | 型クラスタの距離しきい値（表示座標 0..1。同じエージェント同士の距離の平均） |
| `HAND_MIN_N` | `3` | 手札の成立ラウンド数 |
| `HAND_MIN_WINRATE` | `0.5` | 手札の勝率の下限 |

この設定では Split のページは Fade/Neon/Omen/Viper/Yoru、Chamber/Neon/Omen/Skye/Viper、
Astra/Fade/Raze/Viper/Yoru の 3 構成になる見込み。
PRX 構成（44R・full5=8）は「データ不足」で index 行きが正しい結果で、無理にページを作らない。

## ページ構成

### index.html

- 環境内の全構成を表にする：5人の名前、使用チーム、ラウンド数、勝率、直近の試合日、ページへのリンク。
- ページを作らない構成は理由（「データ不足: ラウンド数 23 < 30」「データ不足: 5人そろった配置が 8 件 < 15」など、
  落選した条件と実数）を別の表に書く。
- 旧環境（`ENV_START` より前）の構成はさらに別の表に分ける（ページは作らない）。
- 冒頭に「どれから見ればいいか」として、採用ラウンド数が最大の構成への案内を 1 行書く。

### 構成ページ（この順・各スライドの本文はテキスト行 5 行以内）

本文テキスト行の数え方＝見出し・図・figcaption・表・付録を除いた、`<li>` / `<p>` の数。
検証スクリプトもこの定義で数える。

1. **表紙**：構成の5人（アイコンか名前）、使用チーム、期間、マップ総数・ラウンド数。
2. **環境とマップ**：環境内の全構成の採用数と勝率を横棒グラフ（HTML/CSS のみ）で示し、
   バイタルの地図（`Figure.svg`。Split のバイタルは A Ramps・MID）を 1 枚置く。
3. **なぜこの構成か**：最大 3 つ。各主張は「全体平均との差がしきい値を超えた指標」だけから作り、
   根拠の数字・見本ラウンドの静止図・VODカードを付ける。指標の候補：
   - 設置サイトの偏り（全体との差 15pt 以上）
   - ファーストキル取得率（差 10pt 以上）
   - 特定ノードの勝率（自分の構成・全体のどちらも n>=5 で、全体より 10pt 以上高い。根拠は
     自分の値と全体の値を並べ、差として示す。単独の勝率だけでは根拠にしない）
   - 守りのバイタル占有（1:40 でバイタルに 1 人以上いる割合、差 15pt 以上）

   1 つも通らなければ「他の構成とはっきりした差は出ていない」と 1 行だけ書く。無理に主張を作らない。
4. **押し付ける手札**：守り・攻めの順に手札スライドを並べる。手札の並びは回数の多い順。
   1 スライドに手札の回数と勝率を出す。手札 1 個 = 1 スライドで、動く図（見本ラウンド）+ VODカード +
   「誰が何をするか」最大 5 行（見本ラウンドの各エージェント：1:40 のエリア → 1:20 のエリア + 動詞。
   キル数は書かない）。見本は手札ごとに full5（1:40 に 5 人そろった）ラウンドから選び、
   手札どうしで重複させない。ラベルは「使ったチーム vs 相手」（例 `LOUD vs PRX R3○`）。
   full5 の見本が無い手札は、full5 候補が無い場合と、候補はあるが動く図が作れなかった場合を書き分けて表示する。
5. **配置**：守り・攻めそれぞれの基本配置（最大クラスタの見本図、1:40 の配置 + 1:30・1:20 の層）を出す。
   基本配置は、その側の平均勝率（ピストルを除く・1:40 に 5 人そろったラウンド）を下回る型を選ばない。
   最も多い型がこの条件に合わない場合は、その型を「避けるべき型」として回数・勝敗つきで別に出す
   （基本配置の枠には入れない）。片側が無い場合は、理由（件数不足・クラスタ距離・平均勝率を上回る型が無い、を書き分ける）を文章で書く。
   続けて型の一覧（型名・回数・勝敗・見本への VOD リンク）。「避けるべき型」を含む側は、その旨を必ず本文に書く。
6. **真似る手順**：役割表（エージェント → 序盤の持ち場 = 使用ラウンドで最頻の 1:40 エリア →
   中盤の動き = 最頻の 1:20 エリアへの遷移 → 役割 = kb の role）。
   最初に練習する 3 つ = 手札の上位 3 つの名前を挙げる。
7. **付録**：数合わせ（総数・守り・攻め・除外・ピストル数）、設定値の一覧、GLOSSARY の置き換え表、
   単発の型（名前と回数だけ）、構成不明で外したラウンド数（マップ全体）。

### 型（配置クラスタ）と手札

- 型の対象は「ピストルでない・setup が 5 人そろった」ラウンドだけ。側ごとに分ける。
- 距離は 2 ラウンド間の、同じエージェント同士の表示座標（`mapfig.to_view`）のユークリッド距離の平均。
  リーダークラスタリングで `PATTERN_DIST` 以内をまとめ、`PATTERN_MIN` 未満は「単発」に回す。
- 代表（見本）はクラスタのメドイド（他メンバーとの距離合計が最小。勝ちラウンドを優先）。
- 型名は動きが分かる言葉にする（メドイドの 1:40 のゾーン分布 + 多数派の動き）。
  動作語は側に合わせる（守りの型名に攻め専用の言い回しを残さない）。
  `gamemodel.def_formation` の「形だけ」性格は名前にも本文にも出さない。同じ名前が出たら、
  内容で区別できる短い説明（ゾーン分布＋代表エリア）か連番を付けて一意にする。
- 手札は側ごとに `gamemodel.classify` の全局面ノードを集計し、`HAND_MIN_N` 以上かつ
  勝率 `HAND_MIN_WINRATE` 以上のノードを最大 5 個（回数の多い順。同数は名前順）。
  内部用語は GLOSSARY でプレイヤーの言葉に置き換える。略号（DC・PrP・PoC・BP・BTP）は v5 の出力に一切出さない。

### 動く図

- 見本ラウンドの `gamemodel.snap(r, model, e, tol=8)` を e=0（1:40）・10（1:30）・20（1:20）で取り、
  接敵（最初のキルの e が 20 < e <= 60）があれば 4 節目「接敵」として足す。
  各節目で 3 人以上取れたラウンドだけを見本に使う。
- 駒のラベルはエージェント名そのもの。`?` は出さない。名前が取れない駒は描かない。
- 描画は `deck.motion_html` を使う。背景は `deck.map_data_uri` の結果（回転済み displayIcon の data URI）。
- JS は deck の `MOTION_JS` を複製して v5 側に持ち、`prefers-reduced-motion` のときは自動再生しない
  （初期状態を一時停止にし、ボタン文言を「再生」にする）。CSS は deck の CSS を土台にし、
  14px 未満の font-size をすべて 14px 以上に引き上げる。

## 検証項目（`scripts/validate_playbook_v5.py`）

出力フォルダを引数に取り、全構成ページ + index に対して次を機械検査する。
項目ごとに PASS/FAIL と件数を出し、FAIL があれば終了コード 1。検証は緩めない（通らないときは生成器を直す）。

- 禁止文字列が 0 件：「マップ画像がありません」「場所不明」「None」「?」「形だけ」「推定」「&lt;a 」
  「正しい戦略の模索」「略号」。ただし「?」は URL のクエリ（`?t=`）を除く本文テキストで判定する。
- 空の `<ul>`・空の figcaption が 0 件。
- 各構成ページ：マップ図（`class="mapsvg"` または `class="mo-map"` の背景）5 枚以上、
  動く図（`class="motion"`）3 つ以上、VODカード（`class="vod"`）5 つ以上。
- 見出しの 5 人と、ページ内 manifest の見本ラウンドの構成が一致（manifest に見本ラウンドの
  `comp_key` を記録して照合）。
- manifest の守り + 攻め + 除外 = 総数が構成ごとに一致。
- 型はすべて `PATTERN_MIN` 以上（manifest の型リストで照合）。
- 手札の見本ラベルは「使ったチーム vs 相手」で、そのチームが構成を使ったチームと一致し、本文にも出る。
  手札どうしで見本ラウンドが重複しない。見本は full5。見本なしなら理由文が出る（full5 候補の有無で書き分ける）。
- 基本配置の型はその側の平均勝率以上（manifest の `meets_winrate`）。満たさない型は「避けるべき型」として本文に出る。
  基本配置が無い側は理由文があり、件数不足とクラスタ距離を書き分ける。守り・攻め両側の節がある。
- 守りの型名に攻め専用の言い回し（「深くまで早く入って」など）が混ざらない（manifest の型リストで照合）。
- スライドごとの本文テキスト行が 5 行以内（上の数え方）。
- index.html から全構成ページへのリンクがある。
- font-size の 14px 未満の指定が 0 件。

出力フォルダには構成ごとのページ（`comp_*.html`）、入口の `index.html`、`manifest.json` ができる。
`manifest.json` には構成ごとの total / used_def / used_atk / excluded / full5 / dates / teams /
ページの有無と理由、見本ラウンドの `comp_key` などが入る。

## 使い方

生成：

```
python scripts/playbook_v5.py "<data glob>" --map Split --out <出力フォルダ>
```

- 引数形式は v4 に合わせる（チーム引数は無い）。
- 生成先はリポジトリ外の `~/workspace/valo-opencode/output/playbook_v5/Split/` を想定。
  権限の都合で外に書けない環境では、リポジトリ内の相対パス（例 `--out _v5_check`）を使い、
  確認後はコミットに含めず削除する。

検証：

```
python scripts/validate_playbook_v5.py <出力フォルダ>
```

通らない項目は生成器側を直す（検証を緩めない）。

## テスト

`tests/test_playbook_v5.py`（ネットワークなし・純粋関数のみ）：

```
python -m pytest -x -q tests/test_playbook_v5.py
```

- 構成グルーピング：`comp_key` が違うラウンドが混ざらない。構成不明が除外され数が合う。
- 型クラスタ：合成した位置データで、近い 3 ラウンドが 1 型になり、遠い 1 件が単発になる。
  型名に「形だけ」が含まれない。
- GLOSSARY：内部用語が表示名に置き換わり、略号が出ない。
- VODカード：`yt` URL から ID とサムネイル URL が取れ、HTML に `&lt;a` が含まれない。
- ゲート判定：`PAGE_MIN_*` を満たさない構成がページ対象から外れ、理由が返る。

全体のテストは `python -m pytest -q`（既知の失敗
`tests/test_video_cache.py::test_range_download_matches_source` 1 件以外を増やさない）。
