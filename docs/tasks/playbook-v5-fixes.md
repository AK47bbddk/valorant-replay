# playbook-v5-fixes（v5 の見本選び・根拠・型の採用条件・表示の修正）

※窓口 (Muse) が 2026-11-13 に作成。Claude の v5（Split）レビュー（2026-11-13、青木持参）を受けた修正。ブランチは `task/playbook-v5` から `task/playbook-v5-fixes` を切る。

## 確認済みの事実
- VOD カードのラベルが相手チームのタグだけで作られている（`vreplay/playbook_v5.py:260`、`r.get('opp_tag')`）。Fade 構成（GE・LOUD・NS・VIT）のページに "PRX R3○" と出るのはこのため。データ自体は構成のラウンドだが、表示が誤解を招く。
- 手札の成立条件は HAND_MIN_WINRATE=0.5（manifest の settings）。Astra 構成で守りの手札が 0 枚なのはこの下限で全部落ちたためで、ページに説明が無い。
- 型（基本配置）の成立条件 PATTERN_MIN=3 には勝率の条件が無く、最も多い型がそのまま基本配置になる。Astra 構成の守りの基本配置は 8 回中 1 回勝ちの型だった。

## やること（優先順）

### 1. 見本ラウンドの選び方
- 見本と VOD カードのラベルを「使ったチーム vs 相手」の形式にする（例: "LOUD vs PRX R3○"）。使ったチームは、そのラウンド・その側で対象構成を使ったチーム。
- 見本は手札ごとに、その手札に属するラウンドの中から選ぶ。別の手札と見本ラウンドが重ならないようにする。
- 見本は full5（1:40 で 5 人そろった）ラウンドから選ぶ。full5 の見本が無い手札は、見本なしと分かる表示にする（3人分だけの図を出さない）。
- 動く図の見本も同じ決まりで選ぶ。

### 2. 「なぜこの構成か」の根拠
- 根拠の指標は、構成の値と全体（同マップ・同環境の全構成）の値を並べ、差が分かる形式に統一する。単独の勝率（例: 人数有利時の勝率）だけを根拠に出さない。全体でも同指標を数え、差として出す場合のみ使ってよい。

### 3. 型の採用条件と基本配置
- 基本配置は、その側の平均勝率を下回る型を選ばない。最も多い型がこの条件に合わない場合は、その型を「避けるべき型」として回数・勝敗つきで別に出す（基本配置の枠には入れない）。
- 基本配置と手札は守り・攻めの両側を対象にする。片側が無い場合は、理由（該当ラウンド数、落ちた条件）をページに文章で書く。

### 4. 表示
- 手札スライドに回数と勝率を出す。手札の並びは回数の多い順にする。
- 型名の重複を無くす（同じ名前の別クラスタには、内容で区別できる名前を付ける。決まりは実装で定義し、テストで一意性を固定する）。
- 型名の文は側に合わせる（守りの型に攻め向けの動詞を使わない）。
- 役割表は守りと攻めで分ける。
- 地図を大きくする（図と説明を横に並べるレイアウト）。同じ場所で重なる駒は少しずらして描き、隠れないようにする。

## 検証（scripts/validate_playbook_v5.py を広げて機械で確かめる）

- 手札間で見本ラウンドが重複しない
- 見本が full5 のラウンドである
- 基本配置の型が勝率条件を満たすか、「避けるべき型」と明示されている

- Split を再生成し、検証が全て通る。再生成したページはリポジトリ内の出力先に置く（Drive へのアップロードは窓口が行う）
