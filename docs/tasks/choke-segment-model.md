# choke-segment-model（チョークで切り分けてから割り当てる方式への変更）

※窓口 (Muse) が 2026-11-10 に作成。青木の承認済み（「切り分け方式で実装して」）。
先行の choke-boundary-model（測地距離＋チョーク種、main 取り込み済み）でも、種の効く範囲の外で Main 側が勝ち直し、サイト側への食い込み（B Main の飛び地、A の境界がチョークよりサイト寄り）が残った。パッチを重ねるのをやめ、構造で防ぐ。

## 方式（決定事項）
`vreplay/mapfig.py` の `area_regions` を、kb に chokes があるマップでは次の順に変える:
1. 通路マスク（256 グリッド）から、各チョーク点に切れ目（円形の壁、半径は通路を断ち切れる大きさ。目安 0.025、必要なら「両側が壁に届くまで広げる」適応方式）を入れる。
2. 切れ目で割れた区画（連結成分）ごとに割り当てる:
   - 区画内にコールアウトがある → その区画内のコールアウトだけを種にして、区画内で経路距離で分ける（重み＝バイタル shrink 等は従来どおり）。
   - 区画内にコールアウトが無い → 区画全体を1エリアにする。決め方は、その区画に接するチョークのペア（kb の chokes のエリア名）のうち、区画の重心から直線距離で一番近いコールアウトのエリア。ペア情報が無い場合は全体で一番近いコールアウトのエリア。
   - 切れ目の円内の画素は、最も近い割り当て済み画素のエリアにする（境界線そのものなのでどちらでもよい）。
3. チョーク種（前方式の両脇の種）は廃止する。kb の chokes のペア情報は上記 2 の決定と検証に使う。
4. chokes の無いマップは現行（測地距離のみ）のまま変えない。キャッシュキーには方式タグを更新して旧キャッシュと混ざらないようにする。

## 不変条件（テストで固定すること）
- 各チョークについて、ペアの両側のコールアウトが「切れ目で別の区画」に分かれていること（切れ目が実際に効いていることの検査。効かなければテストが落ちて気づける）。
- サイト側の区画（サイトのコールアウトを含む区画）の中に、入口エリア（A Main / B Main / B Market 等、そのチョークの手前側エリア）の画素が1つも無いこと。Sunset の A Site / B Site で検査する。
- チョークのすぐ先（サイト側へ 0.03 進んだ点）が手前側エリアでないこと（既存のペア検査と併用可）。
- 既存テスト（test_kb / test_playbook_v4 / test_gamemodel / test_tactival / test_meta / test_deck / test_mapfig / test_tactics）が全て通ること。Split の領域が壊れていないこと。
