# spawn-areas-and-elbow-check（スポーン2エリアの追加と、エルボーの表示監査）

※窓口 (Muse) が 2026-11-11 に作成。青木の指示: スポーンバリアを用意し、攻め側スポーン（Tベース）と防衛側スポーン（CT）をエリアとして用意する。あわせて「エルボーが消えている」の監査。

## 1. スポーンエリアの追加（config/kb/maps/sunset.yaml）
- エリアを2つ追加する: `T Spawn`（callouts: [攻撃側 Spawn]）、`CT Spawn`（callouts: [防衛側 Spawn]）。eval は暫定でよい（note に暫定と書く）。vital は false。
- walls に4本追加する（窓口が幅プロファイルで実測した出口のボトルネック点を通り、移動方向に垂直な線分。端点は分離が成立するまで通路幅に合わせて調整してよい）:
  - T北出口: 中点 (0.473, 0.781)、初期値 [0.4595, 0.7957, 0.4865, 0.7663]
  - T東出口: 中点 (0.605, 0.828)、初期値 [0.5909, 0.8139, 0.6191, 0.8421]
  - CT南西出口: 中点 (0.410, 0.141)、初期値 [0.4288, 0.1477, 0.3912, 0.1343]
  - CT東出口: 中点 (0.656, 0.145)、初期値 [0.6695, 0.1303, 0.6425, 0.1597]
- 受け入れ条件（テストにする）: 4本の wall を入れた状態で、攻撃側 Spawn の地点のエリアが T Spawn、防衛側 Spawn の地点のエリアが CT Spawn になり、スポーンの区画が他のエリアと混ざらないこと（スポーン地点から B Lobby / A Lobby / Mid Top / B Market / A Link の各地点へ、wall を越えずに到達できないこと）。

## 2. エルボーの監査と修正
- 現状の確認（窓口の実測）: kb では A Elbow は A Site の callouts にあり、area_regions でもエルボー地点 (0.922, 0.437) と縦帯は A Site になっている。一方、生成したプレイブック（output/cycle5）の本文には "Elbow" が1件も出てこない。
- 調べて直すこと: プレイブック（deck / playbook_v4）の A Site のエリア図にエルボーの帯が描かれているか。位置・セットアップのラベル候補に A Elbow が含まれるか。欠けている場合は描画・ラベル生成側を直す。
- データ側（report.json のセットアップ）に Elbow の出現自体が無いために本文に出ないだけなら、無理に作らず、その旨を報告に明記する。
