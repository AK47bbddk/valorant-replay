# choke-cut-barrier-fix（チョーク分離の検査を局所化し、切れない所は断面バリアで切る）

※窓口 (Muse) が 2026-11-10 に作成し、同日に青木の確認で C10 の解釈を訂正。

## 前提の訂正（重要）
- C10 (0.113, 0.587) は B Main|B Site の境目ではない。B Lobby 側から B Main 通路へ入る入口のチョーク（A 側の A Lobby→A Main と同種）であり、両側とも B Main エリア。窓口の経路実測で確定し、青木も確認済み。
- したがって kb の sunset.yaml で C10 のペアを ["B Main", "B Site"] から ["B Main", "B Main"] へ直す（今回だけ kb の YAML 変更を許可する。他のエントリは変更しない）。
- A Alley|A Site (0.899, 0.319) は、Alley 側の通路が A Elbow（サイト側）へチョークなしでつながるため、コールアウト同士の大域分離は原理的に不可能。検査は「チョーク局所での分離」に改める。

## やること
1. kb: C10 のペアを ["B Main", "B Main"] に修正する。
2. 分離の検査を局所プローブ方式に改める（テストと、必要なら mapfig の切れ目調整の両方）:
   - ペアが異なるエリアのチョークについて、チョーク点から両側の最寄りコールアウト方向へ約 0.04 離れた歩行可能点（プローブ）を取る。
   - 全ての切れ目を入れた状態で、両プローブが別々の区画に属することを必須とする。同一エリアのチョーク（C10・C14）は分離を要求しない。
   - 例外・既知の未解決としての除外は一切しない。分離できない場合はテストが落ちる形にする。
3. 円で局所分離できないチョークは断面バリアで切る:
   - 両プローブを結ぶ経路（通路上の最短路）を取り、経路上でチョーク点に最も近い点で、経路の進行方向に垂直な線分を引く。両端は歩行不可領域に届くまで伸ばす（＋数 px の余裕）。これをそのチョークの切れ目とする。
   - 円で分離できるチョークは今の円のままにする。
4. 既存テスト（test_kb / test_playbook_v4 / test_gamemodel / test_tactival / test_meta / test_deck / test_mapfig / test_tactics）を全て通す。Sunset の領域図を _review/ に再作成する。

## 触ってよいファイル
- `vreplay/kb/maps/sunset.yaml`（C10 のペアのみ）
- `vreplay/mapfig.py`（切れ目の生成まわり）
- `tests/test_mapfig.py`、`tests/test_playbook_v4.py`、`tests/test_kb.py`（検査の付け替え）
- 触らないもの: tactics.py、deck.py、他の kb

## 進め方（前回は解析だけでタイムアウトした。今回は直接実装すること）
- まず kb 修正と検査の付け替えを入れて対象テストを回し、落ちるチョークを確認してからバリアを実装する。プロトタイプの作り直しや長時間の探索はしない。

## 完了の定義
- 除外なしの局所分離テストが通り、既存テストに退行がないこと。レビューパックを作ること。push・マージはしない。
