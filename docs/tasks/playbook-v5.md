# playbook-v5（プレイブック v5：構成単位・図主役への作り直し、Split）

※この指示書は Muse（窓口）が青木の v4 レビュー（2026-11-11）をもとに作成。仕様の正本は青木のレビュー本文で、この指示書はそれを実装可能な形に落としたもの。食い違いがあればレビューを優先し、このファイル末尾の「質問」に書いて止める。

## 目的

v4 は「チーム単位・集計を文章で並べたレポート」で、図がゼロ、構成が混ざる、型が細切れ、攻めが空、という問題がある。v5 は単位を「マップ × 5人構成」に変え、図（マップ図・動く図・VODカード）を主役にした新しい生成器を別モジュールで作る。v4 は残す（置き換えない）。

## やること

### 1. データの組み立て（playbook_v5.py）

- 入力は report.json のリスト。`deck.records()` で全ラウンドを取り、マップで絞る。
- 構成キー = レコードの `comp_key` をそのまま使う（5エージェント完全一致）。`comp_key` が無い・空・`None` や `?` を含むラウンドは「構成不明」として集計から外し、数を数える。
- 環境フィルタ: `date >= ENV_START` のラウンドだけをページ対象にする。古いラウンドは index の旧環境集計にだけ使う。
- 図の準備: `cfg["output"]["dir"]` は生成スクリプトが `--out` 配下の `_work` に差し替える（キャッシュが生成先に自己完結するように）。`deck.map_data_uri(cfg, map, None, callouts)` が空、または `mapfig.Figure.ok` が False なら例外で生成全体を失敗させる。「画像なし」の HTML は絶対に出さない。取得は最大3回まで再試行する。
- 側ごとの使用可否: `gamemodel.setup_at_140(r, model)` が None でないラウンドを「使用」。構成ページの総数 = 使用した守り + 使用した攻め + 除外（setup が取れなかった環境内ラウンド）で必ず一致させる。ピストルは使用数に含める（型・手札の集計からは除く）。
- 出力と同時に `manifest.json` を出力フォルダに書く（構成ごとの total / used_def / used_atk / excluded / full5 / dates / teams / ページの有無と理由）。検証スクリプトはこれと HTML の両方を見る。

### 2. 型（配置クラスタ）

- 対象は「ピストルでない・setup が5人そろった」ラウンドだけ。側ごとに分ける。
- 距離 = 2ラウンド間で、同じエージェント同士の表示座標（`mapfig.to_view(u, v, fig.k)`）のユークリッド距離の平均。
- リーダークラスタリング: 未分類のラウンドを種に、種との距離が `PATTERN_DIST` 以内のものを集める。大きい順に確定し、`PATTERN_MIN` 未満は「単発」に回す。
- 代表ラウンド（見本）= クラスタのメドイド（他メンバーとの距離合計が最小）。勝ちラウンドの中から選ぶ（勝ちが無ければ全体のメドイド）。
- 型名は動きが分かる言葉にする。作り方: メドイドの 1:40 のゾーン分布 + クラスタ内で多数派の動き（`gamemodel.classify` の buildup ノード、または 1:20 時点のゾーン移動）から組み立てる。例:「Midに2枚置いて前に出る」「A寄り3枚で構えて待つ」。人数表記だけの名前、「形だけ」は禁止。
- `gamemodel.def_formation` の「形だけ」性格は使わない（名前にも本文にも出さない）。

### 3. 手札（押し付ける動き）

- 側ごとに `gamemodel.classify` の全局面ノードを集計し、`HAND_MIN_N` 以上かつ勝率 `HAND_MIN_WINRATE` 以上のノードを、手札として最大5個（件数×勝率の順）。
- 内部用語は GLOSSARY（このモジュール内の1 dict）でプレイヤーの言葉に置き換えて表示する。例: 「正しい戦略の模索（ホールド）」→「構えて待つ」、「1人でエリア＋人数をかける」→「薄くなった側を1人で持ち、厚い側に人数を寄せる」、「ビルドアップカウンター」→「前に出てきた相手に合わせて当たる」。置き換え表は付録スライドにも出す。略号（DC・PrP・PoC・BP・BTP）は v5 の出力に一切出さない。
- 手札1個 = 1スライド: 動く図（見本ラウンド）+ VODカード + 「誰が何をするか」最大5行（見本ラウンドの各エージェント: 1:40のエリア → 1:20のエリア + 動詞。動詞は v4 の攻守別辞書の考え方を GLOSSARY 側に寄せて再実装してよい。キル数は書かない）。

### 4. 動く図

- データは見本ラウンドの `gamemodel.snap(r, model, e, tol=8)` を e=0（1:40）・10（1:30）・20（1:20）で取り、接敵（最初のキルの e、20 < e <= 60 のとき）もあれば4節目「接敵」として足す。各節目で3人以上取れたラウンドだけを動く図の見本に使う。
- 駒のラベルはエージェント名そのもの（`?` は出さない。名前が取れない駒は描かない）。
- 描画は `deck.motion_html({"name": タイトル}, fr, bg_uri)` を使う。背景 `bg_uri` は `deck.map_data_uri(...)` の結果（回転済み displayIcon の data URI）。座標は `to_view` 変換後の (x, y)。
- JS は deck の MOTION_JS を複製して v5 側に持ち、`prefers-reduced-motion` のときは自動再生しない（初期状態を一時停止にし、ボタン文言を「再生」にする）変更だけを加える。CSS は deck.CSS を土台にし、11〜13px の指定をすべて 14px 以上に引き上げる上書きを足す（`.foot`・`figcaption`・`.sub`・`.mo-play` 等）。

### 5. VODカード

- レコードの `yt` から動画IDを取り、サムネイル `https://i.ytimg.com/vi/<id>/hqdefault.jpg` のカードにする。リンクは元の `yt`（`?t=秒` 付き＝該当秒から再生）。
- カードの HTML は文字列として直接組み立てる（テキスト用エスケープ関数を通さない）。属性値は `html.escape(..., quote=True)` を1回だけ。

### 6. ページ構成（構成ページ、この順・各スライド本文はテキスト行5行以内）

テキスト行の数え方: 見出し・図・figcaption・表・付録を除いた、本文の文（li / p）の数。検証スクリプトもこの定義で数える。

1. 表紙: 構成の5人（アイコンか名前）、使用チーム、期間、マップ総数・ラウンド数。
2. 環境とマップ: 環境内の全構成の採用数と勝率を横棒グラフ（HTML/CSSのみ）で + バイタルの地図（`Figure.svg`、Split のバイタルは A Ramps・MID）1枚。
3. なぜこの構成か: 最大3つ。各主張は「全体平均との差がしきい値を超えた指標」だけから作り、根拠の数字・見本ラウンドの静止図・VODカードを付ける。指標の候補: 設置サイトの偏り（全体との差15pt以上）、ファーストキル取得率（差10pt以上）、特定ノードの勝率（n>=5 かつ構成全体の勝率より10pt以上高い）、守りのバイタル占有（1:40 でバイタルに1人以上いる割合、差15pt以上）。1つも通らなければ「他の構成とはっきりした差は出ていない」と1行だけ書き、無理に主張を作らない。
4. 押し付ける手札: 守り・攻めの順に手札スライド（3.の形式）。
5. 配置: 守りの基本配置（最大クラスタの見本図、1:40 のアイコン配置 + 1:30・1:20 の層）と攻めの基本の入り方（同）。続けて型の一覧（型名・回数・勝敗・見本への VOD リンク）。
6. 真似る手順: 役割表（エージェント → 序盤の持ち場 = 使用ラウンドで最頻の 1:40 エリア → 中盤の動き = 最頻の 1:20 エリアへの遷移 → 役割 = kb の role）。「主に使うスキル」のデータは無いので作らない。最初に練習する3つ = 手札の上位3つの名前を挙げる。
7. 付録: 数合わせ（総数・守り・攻め・除外・ピストル数）、設定値の一覧、GLOSSARY の置き換え表、単発の型（名前と回数だけ）、構成不明で外したラウンド数（マップ全体）。

### 7. index.html

- 環境内の全構成を表にする: 5人の名前、使用チーム数、ラウンド数、勝率、直近の試合日、ページへのリンク。ページを作らない構成は理由（「データ不足: ラウンド数 23 < 30」「データ不足: 5人そろった配置が 8 件 < 15」等、落選した条件と実数）を書く。
- 旧環境（ENV_START より前）の構成は別の表に分ける（ページは作らない）。
- 冒頭に「どれから見ればいいか」: 採用ラウンド数が最大の構成へのリンクを1行で案内する。

### 8. 検証スクリプト（scripts/validate_playbook_v5.py）

出力フォルダを引数に取り、全構成ページ + index に対して次を機械検査し、項目ごとに PASS/FAIL と件数を出して、FAIL があれば終了コード 1。

- 禁止文字列が0件: 「マップ画像がありません」「場所不明」「None」「?」「形だけ」「推定」「&lt;a 」「正しい戦略の模索」「略号」。ただし「?」は URL のクエリ（`?t=`）を除く本文テキストで判定する。
- 空の `<ul>`・空の figcaption が0件。
- 各構成ページ: マップ図（`class="mapsvg"` または `class="mo-map"` の背景）5枚以上、動く図（`class="motion"`）3つ以上、VODカード（`class="vod"`）5つ以上。
- 見出しの5人と、ページ内 manifest の見本ラウンドの構成が一致（manifest に見本ラウンドの comp_key を記録して照合）。
- manifest の守り + 攻め + 除外 = 総数が構成ごとに一致。
- 型はすべて PATTERN_MIN 以上（manifest の型リストで照合）。
- スライドごとの本文テキスト行が5行以内（6.の数え方）。
- index.html から全構成ページへのリンクがある。
- font-size の 14px 未満の指定が0件。

## v5修正（2026-11-13、`playbook-v5-fixes`）で変わった仕様

Claude の v5（Split）レビューを受けて、上記の仕様のうち次を変えた。

- 見本（動く図・VODカード）のラベルは「使ったチーム vs 相手 R番号○/✕」。使ったチームは、そのラウンド・その側で対象構成を使ったチーム（レコードの `tag`）。
- 見本は手札ごとに、その手札に属するラウンドのうち「1:40 に5人そろった（full5）」ものから選ぶ。手札どうしで見本ラウンドを重複させない（置き場所＝配置の見本も full5 を優先）。full5 の見本が無い手札は、動く図を出さず「見本ラウンドがありません」と表示する。
- 「なぜこの構成か」の根拠は、構成の値と全体（同マップ・同環境の全構成）の値を並べて差で示す。特定ノードの勝率も全体の同じノードの勝率と比べ、10pt 以上の差があるときだけ使う（単独の勝率は根拠にしない）。
- 基本配置は、その側の平均勝率（型と同じ母数＝ピストルを除く full5 ラウンド）を下回る型を選ばない。最も多い型が条件に合わないときは、その型を「避けるべき型」として回数・勝敗つきで別に出す。基本配置と手札は守り・攻めの両側を対象にし、片側が無いときは理由（該当ラウンド数・落ちた条件）を文章で書く。
- 手札スライドに回数と勝率を出す。手札の並びは回数の多い順。
- 型名は側に合わせる（守りは「置いて」、攻めは「集めて」）。同じ名前の別クラスタには、内容（ゾーン分布＋代表エリア）で区別できる名前を付け、守り・攻め両側を通して一意にする（`unique_name`）。
- 役割表は守りと攻めで分ける。地図は大きくし、図と説明を横に並べる。同じ場所で重なる駒は少しずらして描く（静止図は `mapfig` の `spread`、動く図は `playbook_v5` 側で `spread`）。

`scripts/validate_playbook_v5.py` に次の機械検査を足した（`manifest.json` を見る）。

- 見本ラベルの「使ったチーム」がその構成を使ったチームに含まれ、ラベルが本文にある。
- 手札間で見本ラウンドが重複しない。見本は full5。見本が無い手札は「見本ラウンドがありません」と表示する。
- 基本配置の型が勝率条件を満たすか、条件を満たさない型が「避けるべき型」として明示されている。
- 守り・攻め両側の節があり、欠けた側には理由が書かれている。

`tests/test_playbook_v5.py` に次の純粋関数のテストを足した。
`sample_label`（チーム照合）、`sample_candidates`/`sample_key`（full5 優先・重複排除）、
`side_avg_winrate`/`choose_placement`（勝率条件・避けるべき型）、`pattern_name`/`unique_name`（側に合う動詞・一意性）。
