# 指示書: プレイブックv5 段階E（開幕デフォルトの定義修正＋展開の分岐表示）

宛先: 実装エージェント（agy想定）
窓口: Muse / 承認: 青木（2026-11-14、音声指示）

## 背景（定義の食い違い）
現行の開幕の型は、序盤のゾーン分布の積み上げで決めているため「最終的にAへ攻めたラウンド」が Aデフォルトになりやすい。青木の定義は違う。

## E1: デフォルトの定義を「開幕に取りに行くエリア」に変える
- デフォルトは、開幕にどこのエリアを取りに行ったかで決める。最終的に攻めたサイトでは決めない
- 判定は序盤の最初のテイク（エリア支配の成立）またはそれに相当する開幕の前進で決める。リグループして別サイトへ行ったラウンドも、開幕の型は取りに行った側のままにする
- Split の語彙（確定）:
  - Aメインを取りに行く = Aデフォルト
  - Aランプを取りに行く = ランプデフォルト
  - ミッドを取りに行く = ミッドデフォルト
  - Bメインを取りに行く = Bメインデフォルト
- 他マップでは、そのマップの開幕の取り合いエリア（メイン／ランプ／ミッド等に相当するエリア）で語彙を作る
- ラッシュ（開幕15秒以内のエントリー、最優先）と詰め待ち（取りに行かず待つ）は現行のまま残す

## E2: 開幕の型ごとに「展開の分岐」を見せる
各開幕の型について、その後どう展開したかの内訳を付ける。
- 内訳の軸は段階Dのエントリー型（Aセット / Aスプリット / Bセット / Bスプリット / エントリーなし等）とし、件数と勝率を出す
- 例: Aデフォルト 40件 → Aセット 18件、Aスプリット 9件、リグループしてBセット 7件、…
- 件数の多い分岐には代表ラウンド（GIF・VOD）を付ける。少ない分岐は件数だけでもよい
- これにより「BメインデフォルトからリグループしてA」のようなラウンドも、分岐として正しく見えるようにする

## 検証への追加

- 開幕の型ごとに分岐の内訳（合計が型の件数と一致）が出ること
- 段階Dまでの検証がすべて引き続き通ること
