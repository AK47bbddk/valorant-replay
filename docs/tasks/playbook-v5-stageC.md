# 指示書: プレイブックv5 段階C（サイド別再構成）

宛先: 実装エージェント（agy想定）
窓口: Muse / 承認: 青木（2026-11-13、段階Bの目視フィードバック）

## 背景（問題）
段階Bのページは、構成の全ラウンドをサイド無区別にフェーズ分類・集計し、代表例も両サイド混在だった。そのため「防衛の節で攻めの話をする／攻撃の節で防衛の話をする」混線が起きた。青木の目視で発覚。

## 目的
構成ページをサイド別（攻撃／防衛）に分け、各サイドで「序盤の型→中盤→終盤」の3部構成にする。代表例・図・件数はすべてそのサイドのラウンドだけで作る。

## 新しいページ構成（構成ページごと）
共通: 基本配置・役割表は現行のまま残す。以下をサイド別に2ブロック作る。

### 攻撃ブロック
1. 序盤の型: 上位3型（型ごとに件数・勝率・代表例）
2. エントリーの仕方（中盤）: 上位3型
3. 終盤: ポストプラントの形（型として最大3つ）

### 防衛ブロック
1. 序盤の型: 上位3型
2. 中盤の強い動き: 上位3型
3. 終盤: 寄せ方・リテイクの仕方（型として最大3つ。寄せ／リテイクの別を明示）

## 集計ルール
- 既存の `phases.classify_flow` の分類結果を、ラウンドにおける当該構成側のサイド（攻撃／防衛）で分割してから集計する。phases.py 自体は変更しない。
- 分母は「サイド別×分類済みラウンド数」を各ブロックに明示する（例: 攻撃 分類61/82R）。
- 型の選定はサイド内での件数順、上位3つ。3つに満たない場合はある分だけ出す（件数が少なくても型として出す、は既定方針どおり）。
- 代表例（flow要約・GIF・VODカード）は必ず同じサイドのラウンドから選ぶ。
- 図は TactiVal の単一時刻ボード3枚（序盤・中盤・終盤）をサイド別に用意する。描画できない環境では従来どおりボードJSON＋注記に格下げする。
